CampusBoot - Reflection Questions

Q1. What would happen if you forgot @Retention(RetentionPolicy.RUNTIME)?
Without RUNTIME retention, the annotation is not kept in the .class file for the running program (the default is CLASS retention, which the JVM ignores). Methods such as getAnnotation(Component.class) would then return null. As a result, scan() would skip every class, injectValues() would inject nothing, Validator would report no violations, and Router would always return 404. The code would still compile, so the bug would be silent and hard to notice.

Q2. Map each annotation to Spring Boot and name one thing real Spring does that CampusBoot does not.
@Component is equivalent to Spring's @Component, @Value is equivalent to Spring's @Value, @Range is similar to the Bean Validation annotations such as @Min and @Max (or @Range in Hibernate Validator), and @Route is similar to @GetMapping or @RequestMapping. Real Spring does dependency injection between beans (for example with @Autowired and constructor injection), but CampusBoot only injects simple String and int values. Real Spring also runs a real web server and handles HTTP requests, while CampusBoot only matches a path String.

Q3. Why is setAccessible(true) both powerful and risky?
It is powerful because it lets reflection read and write private fields, such as appName in GradeController, so the Container can inject values without setters. It is risky because it breaks encapsulation: code can change private data and skip the checks the class designer wanted. This can create bugs or security problems, and in newer Java versions the module system can block it for some classes. It should be used carefully and only when really needed.
